# macOS 1.4 (110): Native Viewer full screen

## Fix

The Viewer is a secondary SwiftUI `Window`. Its auxiliary/associated role can
prevent it from owning a full-screen Space. Earlier builds only changed the
separate `fullScreenPrimary` flag and the green button's action, leaving that
role conflict unresolved.

- Declare `.windowManagerRole(.principal)` and enable full-screen interaction
  on macOS 15+, while retaining macOS 14 compatibility.
- The AppKit bridge also clears `.auxiliary` and sets `.primary`; it no longer
  replaces the native green-button action.
- Offer Full Screen before connection as well as during a session.
- Keep connection, video/input surfaces, and windowed control preferences
  independent of presentation changes.

Apple reference: [WindowManagerRole](https://developer.apple.com/documentation/swiftui/windowmanagerrole).

## Verification

- Reproduced the pre-fix behavior through the desktop UI: the Viewer exposed a
  Zoom button and clicking it did not enter full screen.
- Build 110 local debug app: desktop interaction verified native green-button
  entry, custom Full Screen/Exit Full Screen, and Control-Command-F entry/exit.
  The completed state reported `fullScreen`, showed screen-filling content
  without the window title bar, then returned to `windowed` with native controls.
- 52 Viewer unit tests passed. Their synthetic full-screen notifications are
  explicitly described as layout/state tests, not native integration evidence.
- Added `SidecarBridgeViewerUI` / `MacViewerFullScreenUITests` to launch the real
  app and verify native transitions and window dimensions. Compilation passed,
  but execution on this machine stopped before test cases with
  `Timed out while enabling automation mode`. This suite is **not reported as
  passed**. No system automation permissions were changed.
- A separately launched ad-hoc-signed test app stalled before main in
  `_libsecinit_appsandbox`; it was stopped. Desktop verification used the
  project's existing `CODE_SIGNING_ALLOWED=NO` local debug build instead.

Real connected Intel-to-M5 streaming and macOS 14 runtime acceptance remain
unverified. The previously reviewed Saved-Mac cleanup visibility and received
versus displayed FPS issues are unchanged by this full-screen-only fix.
