# macOS 1.4 (111): Viewer pairing persistence and removal

## Fix

- A successful Viewer pairing continues to use the saved Keychain credential on
  later connections; the temporary 16-digit code is not retained.
- Saved Macs now expose a per-Mac **Forget** action and a **Forget All Saved
  Macs** action.
- Both removal actions require confirmation. Cancel leaves the saved route and
  Keychain credential unchanged.
- Removing one saved Mac deletes its `pad.mac.<host-id>` credential and route;
  the next connection requires the current Host code once.
- Host-side **Forget All** now also requires confirmation before revoking every
  `mac.peer.*` credential and rotating the pairing code.
- A stale protected-Keychain copy can no longer hide a replacement that was
  successfully written to the legacy Keychain fallback.

- The focused macOS Viewer/ConnectionSetup run executed 64 tests with 0 failures.
- `git diff --check` passed.
- Physical two-Mac reconnect and Keychain acceptance remain manual checks.
