# macOS 1.4 (112): Single Connect pairing flow

## Fix

- Viewer now uses one **Connect** action for both the initial LAN handshake and
  the response to a Host pairing challenge.
- The redundant **Verify Code** action was removed. After a Host requests a
  code, entering it and pressing **Connect** submits the code.
- Incorrect, expired, or rate-limited codes are returned to the Viewer as an
  actionable pairing error; rejected attempts do not create a Keychain trust.
- Existing Saved pairings continue to reconnect without entering a temporary
  code. Forget and Cancel behavior is unchanged.
